# Agent Guidelines

`brownfield-ai` is a standalone agent-orchestration harness. It does **not** live
inside the codebase it works on: the repositories under `repos/` are nested
checkouts of the user's existing ("brownfield") repos, and this workspace layers
skills, protocols, and memory on top of them without modifying them. Treat any
change that would write agent configuration *into* an upstream repo as out of
scope unless the user asks for it explicitly.

## Core Principles & Protocols

1. **Protocol > Speed**: Prioritize correctness. Never skip mandatory steps (e.g., `task repos:reset`).
2. **Workflow Routing**: ALL tasks — including greetings — MUST start by scanning [workflows/INDEX.md](workflows/INDEX.md) to identify the appropriate domain procedure. Greetings trigger [workflows/greeting.md](workflows/greeting.md).
3. **Delegation Mandatory** ([docs/delegation_protocol.md](./docs/delegation_protocol.md)): Planners and Orchestrators are *Managers*. Do NOT code directly. Use your platform's native delegation mechanism (e.g., sub-agent spawning, tool-use delegation). Enforce Least Privilege (JIT). Reviewer agents emit a structured Output Envelope; see [docs/reviewer_envelope.md](./docs/reviewer_envelope.md).
4. **Verification** ([docs/verification_protocol.md](./docs/verification_protocol.md)): The Orchestrator must NEVER self-validate. Use `task` for tests and `code-review` agents to check outputs. Deny hallway passes or suppressed linter masks. You are STRICTLY FORBIDDEN from using inline linter bypass comments such as `# noqa`, `# type: ignore`, `# shellcheck disable`, etc.
5. **Planning** ([docs/planning_protocol.md](./docs/planning_protocol.md)): Do NOT write code. Planners design architecture and initialize context by querying the Execution Ledger (`execution-ledger index-epics` and `execution-ledger resume` for active epics). Drafts must be dual-model reviewed before Orchestrators delegate execution. Plans default to vertical slicing — see [docs/vertical_slicing_guide.md](docs/vertical_slicing_guide.md) for decomposition guidance and [docs/planning_protocol.md](docs/planning_protocol.md) §3 for the full decision process.
6. **Memory & Context Drift**: Check [docs/learnings.md](docs/learnings.md) and query ChromaDB before assumptions. If you encounter repetitive errors, confusion, or context drift, stop and explicitly invoke the `protocols` skill to realign with core repository rules. Crystallize new context. Query the Execution Ledger (`execution-ledger resume`) to bootstrap context when resuming an in-progress epic.
7. **No Faking** ([docs/verification_protocol.md](./docs/verification_protocol.md)): Never fake schemas, data, or tests. If tools/directories are missing, halt.
8. **Code Consistency**: Mimic surrounding file structure. No new design patterns unless requested. For `workflows/<domain>/CONTEXT.md`, new Skill or Prompt links MUST include a single-line, intent-rich description.
9. **Hygiene** ([docs/maintenance_guidelines.md](./docs/maintenance_guidelines.md)): `task repos:reset` requires explicit user permission ("PROCEED WITH RESET").
10. **Artifacts (CRITICAL CONSTRAINT)**: Store all scratch files, bash redirections, and terminal outputs solely in the workspace-relative `tmp/` directory (e.g., `> tmp/output.log`). **NEVER** pollute the workspace root, and **NEVER** use the OS absolute `/tmp/` directory. Using `/tmp/` causes permission blocks that break the autopilot execution loop.
    - **CRITICAL: Use the Write tool to create new files. Do NOT use `cat` heredocs or Bash redirection.** The Bash sandbox's injection detector rejects heredocs containing Python type annotations (brace adjacent to quote character) — this is a platform-level constraint that cannot be configured away.
11. **Environment Isolation** ([docs/delegation_protocol.md](./docs/delegation_protocol.md)): Execute production workflows strictly in Docker containers. Test execution uses Docker for `test:scripts` and `test:brownfield_ai` (requires LocalStack). Two host-side exceptions run in a local `.venv/`: (1) `test:skills` — `claude -p` (headless mode) requires OAuth via the host session; no `ANTHROPIC_API_KEY` is available for container-based execution. (2) `test:container-integration` — the tests build and exercise real Docker images end-to-end, and auto-skip when `/.dockerenv` is detected (running them nested inside `pytest-cli` would produce a false-green because nested-compose mount paths diverge). The `test:container-integration` path invokes `docker/shared/python-security-gate.sh` before launching host-side pytest; `test:skills` runs pytest directly under `.venv/` — its host OAuth scope and CLI preconditions are its own boundary. Container execution in `python-cli`, `pytest-cli`, and `infra-lint` is enforced by a 3-layer security gate (PreToolUse hooks + host-side validation + container entrypoint). `agent-cli` uses a simplified entrypoint allowlist (no host-side gate artifact). **Direct `python3`/`python` execution on the host is blocked by the PreToolUse hook.** To run ad-hoc Python scripts, write them to `tmp/` and use `task run:adhoc -- tmp/script.py`. See [docs/tool_chain.md](./docs/tool_chain.md) and [docs/container_security.md](./docs/container_security.md).
12. **Exploration**: Follow a tiered discovery strategy — local guides first, remote search second, cloning last:
    1. **Local guides**: Scan [docs/repo-guides/](docs/repo-guides/) for a matching repo or domain guide before any remote call. These are curated, authoritative, and zero-cost. Use the `repos-guide` skill to surface them. Guides are generated for your own repos by the `repos-research` prompt.
    2. **Remote search**: Use the `github-search` skill for cross-repo discovery, org-wide code search, or when the inquiry scope extends beyond what local guides cover.
    3. **Sparse clone**: Only when deep multi-file analysis is required. Prefer sparse checkouts over full clones.
    Agents MUST use `task gh:*` and `task git:*` aliases instead of invoking `gh` or `git` directly.
13. **Step Verification** ([docs/verification_protocol.md](./docs/verification_protocol.md)): At the end of every step: read `plan.md`, test rules against [CLAUDE.md](CLAUDE.md), explicitly stage your files (`task git:add`), then delegate `task test:staged` and `task lint:staged` (skip `test:staged` if docs-only). After lint/test pass, checkpoint a `step_result` artifact to the Execution Ledger via `execution-ledger checkpoint`. Pre-push gates in `auto-pr` and `ship` use `task lint:changed` / `task test:changed` (branch diff vs main) for broader coverage.
14. **Skill-First**: Review `.claude/skills/*` before executing manual `scripts/` fallback logic.
15. **Pre-flight Auth** ([docs/delegation_protocol.md](./docs/delegation_protocol.md)): Sub-agents are headless. Main session MUST run `aws-vault-auth` to securely export short-lived STS credentials to `tmp/.aws-credentials.env` and source them dynamically prior to sub-agent invocation.
16. **Headless Session Protocol** ([docs/delegation_protocol.md](./docs/delegation_protocol.md)): Default mode is interactive. Headless mode is activated by `CI=true` env var or explicit pipeline signal. Skills hitting interactive gates in headless mode without an explicit fallback MUST fail-closed. Delegating agents MUST propagate the headless signal to all subagents and pass `--env CI=true` to Docker containers.
17. **Task Permission Baseline**: The production `.claude/settings.json` permission surface is an **enumerated allow list** of eight `Bash(task <ns>:*)` entries (`agent`, `findings`, `gh`, `git`, `ledger`, `lint`, `test`, `todo`) — not a `Bash(task *)` wildcard. Authors of new task targets MUST confirm their transitive-nesting chain (one `task` invoking another via `deps:` or `cmds:`) resolves without relying on an unowned wildcard — each top-level invocation must either fall under one of the allowed namespaces or be explicitly added through review. See [docs/tool_chain.md](./docs/tool_chain.md) §Task Permission Baseline for the architectural rationale + [docs/container_security.md](./docs/container_security.md) Layer 0 for the fail-closed-by-environment design and rollback recipe. Destructive or code-executing namespaces (`run:*`, `repos:*`, `aws:*`, `ralph:*`, etc.) live **outside** the allow list by exclusion — invoking them from a Claude session prompts the user, which is the interactive-confirmation contract. Task-level deny entries are deliberately not used for `Bash(task ...)` patterns; content-based hook denies in `.claude/hooks/` handle per-target rules (e.g., `sh:<gated>`, `CI=` env-var prefix) where exclusion would be too coarse. One destructive subtarget, `ledger:check-reviews`, is reachable via the `ledger:*` allow by design — the operator (ralph autonomous runner, user terminal, or user asking a Claude session to sweep review states) is the authorization boundary for the PR-close mutations it performs, not the permission matcher. The operator-authorized set is pinned in `tests/hooks/test_settings_permission_baseline.py` (`OPERATOR_AUTHORIZED_DESTRUCTIVE`); any additions require an explicit trust-model review.

18. **Subagent Result Relay — Dispatch Read-Only Agents Synchronously** ([docs/delegation_protocol.md §3](./docs/delegation_protocol.md)): A **named** backgrounded in-process `Agent` dispatch can report its result back ONLY via `SendMessage` (an *unnamed* background subagent instead returns its final message via a completion task-notification). **No agent definition in `.claude/agents/` grants `SendMessage`** — verified by sweep: `code-review*`, `codex-reviewer*`, `gemini-reviewer*`, `copilot-reviewer*`, `explore*`, `qa-standards*`, `qa-lint`, `qa-test`, `task`, `deep-researcher*`, `planner*`, `orchestrator`, `general-purpose*`, and `tdd-*` are all Read- or Read/Edit/Bash-restricted. A **named** background dispatch of any such type is promoted to a persistent in-process teammate that finishes its analysis, emits the deliverable as its final-turn text, then goes idle — with no tool to push that text back to the caller. The result is stranded in the subagent transcript (reading it directly overflows the caller's context — it is the full JSONL transcript, not a summary), so the work must be re-run from scratch. This is pure, recurring token waste. **RULE: never pass `name` when dispatching a no-`SendMessage` agent type.** `name` is the lever that promotes a dispatch to a persistent mailbox-routed teammate, and it is the discriminator available in every harness — some `Agent` tool surfaces expose no `run_in_background` parameter at all, which makes "dispatch synchronously" unactionable while "dispatch unnamed" always works. Where `run_in_background` *is* exposed, also set it to `false`: the final message then returns inline in the tool result. Either way concurrency is preserved — multiple `Agent` calls issued in one message run in parallel and return together, so a review panel loses no wall-clock. Reserve named dispatch for (a) `agent-team`'s tmux teammates (full `claude` processes that DO have `SendMessage`/`TaskUpdate`), or (b) nothing else. An unnamed subagent returns its final message via a completion task-notification and cannot strand. Decision test before naming any `Agent` call: *does this `subagent_type` grant `SendMessage`?* If no → do not name it. **The reviewer bridges are the most expensive place to get this wrong** — a stranded `codex-reviewer*`/`gemini-reviewer*` dispatch still runs its CLI and writes `tmp/<bridge>-review-output-<N>.md`, so when a dispatch does strand, read that artifact rather than re-running the review.

## Tool Chain & PR Protocol

- [Tool Chain](./docs/tool_chain.md) — Task, Terraform, GH CLI.
- [PR Protocol](./docs/pr_protocol.md) — Mandatory user review before merge. **Binds every *agent-issued* `gh pr create|comment|edit|merge`, including ad-hoc calls made outside the `auto-pr` / `ship` skills.** Deterministic tooling that renders a body from a checked-in template (e.g. `src/brownfield_ai/tools/ralph/pr.py`) is out of scope — it has no drafting step and no Write tool.
  - **Always `--body-file`** when the call supplies body text — never inline `--body` / `-b` (via `task gh:pr -- ...` per Principle 12). A metadata-only edit (labels, reviewers, title) passes **no** body flag at all; do not add one, as that would overwrite the current body.
  - **Write the artifact with the Write tool** into `tmp/` — never a heredoc or shell redirection.
  - **Follow the body/comment templates** and the §"Writing Style (Mandatory)" bullet-first rules.
  - **PRs we did NOT author** — write `tmp/pr<number>/pr_review_findings.md`; mark it `<!-- pr-review:review-findings -->` on line 1 (never a `pr-lifecycle:` marker — that namespace is reserved for PRs we own and is what a future reconciliation step will supersede and delete); state the **reviewer roster and models**; mark unverified claims **explicitly unverified**; report findings without resolving them; and **never post without explicit user sign-off**. Headless: write the artifact and halt.
  - Artifact-level style and mechanics are carried by [pr.artifacts.md](./.claude/rules/pr.artifacts.md).
