# AWS Glue Catalog Schema Retrieval

Use this skill to fetch the exact schema definition for a table stored in the AWS Glue Catalog.

## Prerequisites

- **Environment Isolation**: You MUST NEVER execute scripts or tools directly on the host (e.g., do not run `python ...`). You MUST use the [docker-compose.yml](../../../../docker-compose.yml) services.
- **Python Script**: [scripts/get_glue_catalog_schema.py](../../../../workflows/data-engineering/skills/glue-catalog-schema/scripts/get_glue_catalog_schema.py) must be present.
- **Delegation Protocol**: The Orchestrator MUST NOT run terminal commands directly. You MUST use a subagent.

## Workflow

### 1. Preparation and Authentication

#### Pre-flight Authentication

You MUST NOT use `aws-vault exec` wrappers directly anymore. You must first use the `aws-vault-auth` skill to fetch the temporary session tokens, and then prepend those `export AWS_...` strings to any `docker` or `docker compose` command, explicitly passing them into the container.

**Lazy Auth Enforcement**: You must catch `ExpiredToken` or `AccessDenied` errors returned by subagents or scripts and gracefully re-invoke the `aws-vault-auth` skill to refresh credentials and retry the failed command.

## 2. Execution via Delegation

You must fetch the database name and the table name from the user or the context. If the user didn't specify either, prompt them.

`--database` is **required** — Glue database names are account-specific, so this skill ships with no default. If the user's environment has a naming convention (e.g. a `_curated` / `_raw` layer split), infer the matching database from the wording of the request; otherwise ask.

You can optionally support different output formats (markdown, json, raw, mermaid, ddl).

**CRITICAL DIRECTIVE (Delegation Protocol)**: The Orchestrator MUST NOT run terminal commands directly in a multi-agent team environment. You MUST delegate the execution by spawning a subagent via your platform's native mechanism to run the exact command required based on the environment.

**Standard Execution (AWS):**

```bash
<FETCHED_EXPORT_STRINGS>; docker compose run -e AWS_ACCESS_KEY_ID -e AWS_SECRET_ACCESS_KEY -e AWS_SESSION_TOKEN --rm python-cli python3 workflows/data-engineering/skills/glue-catalog-schema/scripts/get_glue_catalog_schema.py --database <DATABASE_NAME> --table <TABLE_NAME> --output-format <FORMAT> --mode <MODE>
```

*(Default format is `markdown` if not specified. Allowed formats: `markdown`, `json`, `raw`, `mermaid`, `ddl`, `struct-type`. Mode can be `glue` or `spark`)*

For the `--mode` and `--output-format` parameters, apply the following intelligence:

- If the request explicitly mentions "Spark structype", "struct-type", "pyspark" or python schema code, use `--output-format struct-type` and `--mode spark`. **CRITICAL**: Do not reinvent or rewrite the PySpark code yourself! You MUST return the exact raw output block generated by the script verbatim.
- If the request mentions "Spark" or requests Spark-specific outputs generally (but not python code), use `--mode spark`.
- If the request mentions "glue" or does not specify, default to `--mode glue`.

### 3. Error Handling and Verification (No Faking Protocol)

**CRITICAL DIRECTIVE (No Faking)**: Never fabricate or guess schemas if the API call fails or if the table is missing.

- The delegated agent MUST surface the exact AWS error (e.g., `AccessDenied`, `EntityNotFoundException`) back to the Orchestrator for root cause diagnosis.
- If the table does not exist or the script fails, do not attempt to guess or create dummy schema outputs to pass checks. You MUST report the failure correctly by returning the EXACT raw error message from the script.
